## 3. Review of Open Questions from Workstream A (Q-B1 to Q-B12)

Workstream A drafted `contracts/context_manifest.json` (C3) and `contracts/evaluation.json` (C4), listing 12 explicit open questions for Workstream B. Here are Workstream B's official architectural determinations:

### Context Manifest & Token Accounting (C3: Q-B1 to Q-B6)

- **Q-B1: Who sets `budget.token_limit` — repair consumer or retrieval producer?**
  - **Determination:** The **repair orchestrator / evaluation harness sets the budget limit** based on experiment configuration and model context windows. The retrieval producer receives this limit, enforces it during selection, and records both `budget.token_limit` and `totals.tokens` in the manifest. The contract rule `totals.tokens <= budget.token_limit` remains an invariant.
- **Q-B2: Budget scope — evidence-only or including repair prompt scaffolding?**
  - **Determination:** `budget.token_limit` in the manifest is **strictly evidence-only** (retrieved source code, signatures, and graph paths). Prompt scaffolding (system instructions, issue description, formatting rules, patch instructions) is budgeted separately by the repair orchestrator. This decoupling ensures retrieval ablations are pure and not skewed by prompt variations.
- **Q-B3: Tokenizer compatibility — tiktoken encoding vs model selection.**
  - **Determination:** The configurable tokenizer interface in C3 (`cl100k_base` with `char_div_4` fallback) is **approved**. For modern LLMs (Anthropic Claude 3.5, OpenAI GPT-4o, DeepSeek), `cl100k_base` provides accurate token estimates within ±5%. All estimates will continue to declare `estimated: true` and record the encoding.
- **Q-B4: `evidence_id` stability across runs.**
  - **Determination:** **Deterministic across runs.** Cross-run stability is required so that incident memory records and verification certificates can unambiguously cite evidence nodes across different experimental runs. Derivation rule: `sha256(f"{repo}#{revision}#{file_path}#{symbol}#{lines}#{source}")[:16]`.
- **Q-B5: Transport format for context manifest.**
  - **Determination:** An in-memory Pydantic model (`ContextManifest`) implements the Python API boundary. It serializes to/from JSON for disk persistence (`artifacts/runs/{run_id}/context_manifest.json`), evaluation datasets, and REST/FastAPI endpoints.
- **Q-B6: Raw content policy.**
  - **Determination:** Each `EvidenceItem` in the manifest carries both `content: str | None` and `content_hash: str`. For code snippets, inlining the bounded snippet directly in the manifest avoids re-reading dirty worktrees and guarantees reproducibility. `content_hash` ensures cryptographic integrity against the base commit.

### Evaluation, Metrics & Ground Truth (C4: Q-B7 to Q-B12)

- **Q-B7: Ground-truth derivation & normalization.**
  - **Determination:**
    1. The existing frozen set `eval/cases/requests_swe_bench_candidates.json` is preserved as **read-only**.
    2. Ground-truth functions are defined as the enclosing function/method of modified hunks in the gold human patch (`patch`).
    3. We endorse Person A's proposal to isolate or flag vendored code (`requests/packages/*`) in secondary analyses.
    4. For repair evaluation, ground truth is objectively verified by test outcomes: `FAIL_TO_PASS` tests must transition to PASS, and `PASS_TO_PASS` tests must remain PASS.
- **Q-B8: Primary vs secondary k values.**
  - **Determination:**
    - **Primary k: 10**. Rationale: balances developer inspection and bounded token budgets (top-10 functions fit within 8k-16k tokens alongside graph relations and test outputs).
    - **Secondary k: 5 (strict), 20 (lenient)**. All evaluation reports will report k ∈ {5, 10, 20}.
- **Q-B9: File-level vs function-level metrics.**
  - **Determination:**
    - **Primary:** Function-level Hit@k and Recall@k.
    - **Secondary / Diagnostic:** File-level Hit@k and Recall@k.
- **Q-B10: Case-set fingerprint method.**
  - **Determination:** The current formula `sha256(json.dumps([sorted((c.case_id, c.revision) for c in localizable), contract_version], separators=(",", ":")))` is **approved** without modification (fingerprint `da1c89d31006ac65753d31fcb719b457ce5cb000e14e0735126018a90e350858`). Excluded cases are strictly omitted from the fingerprint.
- **Q-B11: Multi-function fixes.**
  - **Determination:**
    - **Primary Hit@k:** Any-hit (1 if ≥1 ground truth function appears in top-k).
    - **Required Companion:** Micro-recall@k (total ground truth functions retrieved in top-k / total ground truth functions across evaluated cases) and Macro-recall@k.
    - **Diagnostic:** All-hit@k (1 only if all ground truth functions appear in top-k).
- **Q-B12: Initial dataset (D8) & Contamination Disclosure.**
  - **Determination:**
    - We approve the 44 `psf/requests` SWE-bench cases as the frozen evaluation set for the primary controlled study.
    - Contamination disclosure: Explicitly record `pre_cutoff = 100% (44/44)` in all evaluation reports.
    - Selection of **3 anchor cases** for initial end-to-end integration and smoke verification:
      1. `psf__requests-1142` (single-function bug in `PreparedRequest.prepare_content_length`, simple reproducer `test_no_content_length`).
      2. `psf__requests-1327` (transport adapter ordering in `Session.mount`, tests `test_transport_adapter_ordering`).
      3. `psf__requests-1339` (case-insensitive dictionary bug in `CaseInsensitiveDict.__setitem__`, tests `TestCaseInsensitiveDict`).

## 4. Shared Contracts Proposals Owned by Workstream B

Workstream B proposes three new formal machine-readable contracts in `contracts/`:

### 4.1 `contracts/repair.json` (C5: Repair Orchestration & State Machine)
- **Lifecycle States:**
  `RECEIVED -> CONTEXT_READY -> PATCH_GENERATED -> PATCH_VALIDATED -> VERIFICATION_RUNNING -> VERIFIED | FAILED | REJECTED`
- **State Transition Invariants:**
  - Forward transitions only; terminal states are immutable.
  - Failures are explicit: `PATCH_GENERATION_FAILED`, `PATCH_VALIDATION_FAILED`, `VERIFICATION_FAILED`, `RETRY_EXHAUSTED`, `TIMEOUT`, `CANCELLED`.
  - Retries must increment `attempt_number` and record explicit `retry_reason`. Max retries capped by policy (default 2).
- **Patch Representation:**
  - Unified diff format (`diff --git a/... b/...`).
  - Parsed into structured `CandidatePatch` containing `files_touched: list[str]`, `hunks: list[Hunk]`, `additions: int`, `deletions: int`, `patch_hash: str`.
- **Patch Safety Validation Policy:**
  - Reject absolute paths or path traversal (`../`).
  - Reject modification of prohibited files: `.git/*`, `.github/*`, CI files (`.circleci`, `.travis.yml`), security/credential files (`.env*`, `*.pem`, `*.key`), package metadata (`pyproject.toml`, `setup.py`, `setup.cfg`).
  - Size bounds: `max_changed_files` (default 5), `max_changed_lines` (default 200).
  - Revision check: patch must apply cleanly (`git apply --check`) against target base revision.

### 4.2 `contracts/verification.json` (C6: Sandboxed Verification)
- **Verification Request:**
  - `case_id: str`, `base_revision: str`, `patch: str`, `test_identifiers: list[str]`.
  - `limits: { timeout_seconds: int, max_output_bytes: int, max_memory_mb: int }`.
- **Multi-Tier Sandbox Architecture:**
  - **Tier 1 (Worktree Isolation - Default / Service-Free):** Disposable `git worktree` in a temporary directory (`tempfile.TemporaryDirectory`). Isolated working copy, pinned revision, patch applied via `git apply`, isolated subprocess execution with environment scrubbing (all API keys and host secrets removed), strict execution timeouts (`subprocess.TimeoutExpired`).
  - **Tier 2 (Docker Container - Integration Marker):** Network-disabled container (`--network none`), memory limits (`--memory 2g`), temporary read-write workspace, clean container environment. Gated behind `@pytest.mark.integration` when Docker daemon is running.
- **Verification Result Taxonomy:**
  - `status: VerificationStatus`:
    - `VERIFIED`: Declared `FAIL_TO_PASS` tests passed, and all `PASS_TO_PASS` regression tests passed.
    - `TEST_FAILED`: Test suite executed, but one or more tests failed or regressed.
    - `SETUP_FAILED`: Test runner failed before executing tests (syntax error, dependency missing in target revision).
    - `TIMEOUT`: Execution exceeded `timeout_seconds`.
    - `PATCH_REJECTED`: Candidate patch could not be parsed or failed safety validation.
    - `ENVIRONMENT_ERROR`: Sandbox creation, worktree creation, or disk error.
  - Structured fields: `exit_code`, `passed_tests`, `failed_tests`, `skipped_tests`, `duration_seconds`, `stdout_tail`, `stderr_tail`, `evidence_hash`.

### 4.3 `contracts/incident_memory.json` (C7: Verified Incident Memory)
- **Lifecycle States:**
  `OBSERVED -> ATTEMPTED -> VERIFIED | REJECTED`
- **Memory Record Schema:**
  - `incident_id: str`, `case_id: str`, `repo: str`, `revision: str`, `bug_report: str`.
  - `retrieved_evidence_ids: list[str]` (exact provenance linkage).
  - `candidate_patch: str`, `patch_hash: str`.
  - `verification_summary: VerificationSummary` (`test_suite`, `exit_code`, `status`, `duration_seconds`).
  - `model_metadata: { provider: str, model: str, temperature: float }`.
  - `root_cause_explanation: str | None`.
  - `explanation_verified: bool` (strictly `False` unless proven by formal verification; prevents model hallucination from contaminating memory).
  - `eligibility_status: EligibilityStatus` (`ELIGIBLE`, `INELIGIBLE`).
  - `rejection_reason: str | None`.
  - `created_at: ISO-8601 UTC`.
- **Strict Eligibility Rules:**
  1. Only records with verification outcome `VERIFIED` and `test_pass == true` are eligible for reuse in retrieval context packages.
  2. Unverified explanations must NEVER be presented as established facts or ground truth.
  3. Failed repair attempts are retained as negative evidence (anti-patterns) with `eligibility_status: INELIGIBLE` for standard repair retrieval.
  4. Chronological isolation: A memory record is strictly forbidden from being queried or retrieved if its `created_at` timestamp is `>=` the target case timestamp, preventing future leakage.

## 6. Risks & Mitigations

| # | Risk | Impact | Mitigation |
|---|---|---|---|
| **R-B1** | Docker daemon down on Windows host | Phase 3 containerized verification cannot run | Multi-tier sandbox: Implement robust disposable `git worktree` isolation as the service-free default; gate Docker execution behind `@pytest.mark.integration`. |
| **R-B2** | Model hallucinates arbitrary shell commands | Remote code execution on host | Strict command allowlist: The model generates ONLY unified diffs. The orchestrator controls the execution commands (`pytest <test_id>`), not the model. |
| **R-B3** | Candidate patch attempts path traversal or edits CI/secrets | Host compromise or repo corruption | Comprehensive `PatchValidator`: Inspect every hunk header and target path; reject `../`, absolute paths, symlinks, and edits to `.git/`, `.env*`, CI scripts, or package configs. |
| **R-B4** | Future-information leakage during chronological replay | Invalidation of research conclusions | Strict chronological replay filter in `evaluation/replay.py`: Every case pins the repo to pre-fix SHA; retrieval and memory queries filter `created_at < case.created_at`; target fix commit is excluded. |
| **R-B5** | Model provider costs or rate limits during evaluation | Evaluation halted or expensive | Multi-level caching and stub/mock providers: Fast mock provider for unit tests; disk-based response cache for replay experiments; bounded retries. |
| **R-B6** | Overstated repair claims from passing incomplete tests | Research invalidation | Clear distinction between `TESTS_PASSED` on a subset vs `VERIFIED` on full `FAIL_TO_PASS` + `PASS_TO_PASS`. Every report explicitly states the exact test suite executed. |
| **R-B7** | Inconsistent test environments across historical commits | Target repo test setup failures | Preflight environment check: Verify base commit environment before running repair; record `SETUP_FAILED` separately from repair failure; never fabricate outcomes. |
| **R-B8** | Memory contamination from unverified root-cause explanations | Model hallucination amplified in memory | Strict eligibility gate: Root-cause explanations carry `explanation_verified: false` by default; only patches passing verified sandbox suites enter reusable memory. |
